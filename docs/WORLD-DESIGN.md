## 1. 现状（实读结论）

### 1.1 联机模型：房间 = 独立副本

- 玩家在比奇城组队面板建房（`createRoom`：选 `stageKey` + `layer`，得 5 位房间码）或输码进房（`joinRoom`）；**每间房最多 4 人**（`ROOM_MAX = 4`）。
- 房间是服务端唯一的共享状态，字段只有：`stageKey / layer / sharedKills / bossMax / bossHp / bossState / holeKilled`（artifact `server/src/actions.ts` 的 `rooms` 表；联机版 `lib/actions-shim.js` 的内存 overlay 同款）。
- 回城 = 离开房间（`goToCity` 调 `leaveRoom`）；房主离开或无人时房间解散。联机版房间保留 5 分钟（`STALE_MS = 300000`），**artifact 仍是 20 秒（`STALE_MS = 20000`）——两边已漂移，实施前要统一**。
- 另有一个**正在进行中的房间列表功能**（artifact 客户端已有 `listRooms` 动作 + 组队面板 2.5 秒轮询，`App.tsx` 约 8387 行起；联机版 overlay 也已加 `listRooms`）：点一行直接进房，不用输码。

### 1.2 怪物：现在是每台手机自己算

这是世界制要改的最大一块。客户端 `App.tsx` 的战斗是**本地模拟**：

- 每层进图第一帧**一次性把整层怪全部刷出**（`spawnLeft = monsterCount`，主循环 `while (b.spawnLeft > 0) spawnEnemy()`，`App.tsx` 约 6073 行）。刷出位置全图随机散布（离玩家 ≥220，不压障碍物；白日门野外不刷进城里和海里）。
- 怪物对象字段：`id / def(kind,lv,emoji,name,hp,spd,dmg,xp,r,color,range) / x / y / hp / maxHp / spd / dmg / xp / r / boss / gold / slowT / stunT / atkCd / hitT / teleportCd / charmT / defV / mdefV / seed / aggro / walkPhase`。
- 怪物 AI 在客户端主循环每帧跑（`requestAnimationFrame`，约 60Hz）：未惊动时原地附近游荡（速度 ×0.22）；玩家进警戒距离 `AGGRO_RANGE = 120` 或先挨打就惊动，追击（速度 `spd`，减速 ×0.45）、近战 `atkCd 0.95s`、远程怪（`def.range > 0`）进射程停步掷飞斧（`eprojs`）、沃玛教主瞬移（`teleportCd 3.5–5s`，距离 >190 时瞬移到玩家身边）。
- **怪物之间分离是 O(n²) 全量配对**（`App.tsx` 约 6420 行：`alive` 两两比对，`min = a.r + c.r`）。一层 300 只怪 = 每帧约 4.5 万对。客户端能跑，服务端照搬会贵，必须改空间哈希（见 §2.3）。
- 怪死了**不再补刷**（`spawnLeft` 只减不增）；换层/重进图才重新刷满。Boss 每层一只，进图即刷在离玩家 850–1250 的远处，惊动前只在刷新点附近游荡。
- 多人血量加成（本地算）：普通怪 `hpMul × (1 + 0.25 × (members − 1))`，Boss `bd.hp × (1 + 0.6 × (members − 1))`，`members` = 同房同层人数（含自己）。

### 1.3 服务端现在只同步这几样（心跳 1.2 秒）

客户端 `doHeartbeat`（`App.tsx` 约 5570 行）每 1.2 秒 POST 一次 `heartbeat`，上报：位置 `x/y`、血量 `hp/maxHp`、层 `layer`、自己打怪得的经验 `xpDelta`、对共享 Boss 的伤害 `bossDamage`、Boss 首次刷出时的满血 `bossSpawnMax`、层推进 `advanceLayer`、洞口黄衣僵尸已打掉 `holeKilled`、外观串 `gear`；击杀数 `killsDelta` 另走一次 `flushKills` 心跳单独发。服务端返回整房状态：`members`（每人位置/血量/层/外观/累计经验 `xpTotal`）、`sharedKills`、`bossMax/bossHp/bossState`、`holeKilled`、本人有资格的 `rolls`。

**关键点：服务端没有任何怪物状态。** 它只存：击杀总数、Boss 血量（谁先报满血谁定 `bossMax`，伤害累减，`bossState` 0→1→2）、洞口状态、每人累计经验、Roll 会话。怪物位置、血量、仇恨全在各手机本地——**两个人看到的根本不是同一批怪**，只是击杀数和 Boss 血量对得上。

- Boss 击杀同步：队友打死 Boss 后本机收到 `bossState = 2`，本地 Boss 立刻走击杀结算（`killEnemy(boss, { ownerId: "__teammate__", noRewards: true })`）：掉落照常在本机生成但归属记为队友（1 分钟保护期本机捡不了），经验与击杀数不重复结算，通关结算照常走 `onBossKilled`。
- 通关条件 = **杀本层 Boss**（`onBossKilled`，`App.tsx` 约 4959 行）：非最后一层开传送门（走入口下潜），最后一层记通关、按连接表解锁相邻地图。`killTarget`（每层 120–200）只存在于 `game-data.ts` 的层定义里，**客户端没用它当通关条件**。`sharedKills` 目前只是显示数（多人时击杀显示取 `max(本地 kills, sharedKills)`）。
- 层推进是**全房同步**的：一个人走入口下潜，`pendingAdvance` 随心跳上报，服务端整房 `layer` 前进并清零 `sharedKills`/Boss；其他人收到 `res.layer > 本层` 就跟着 `advanceLayer`。

### 1.4 组队经验与 Roll（2026-11-24 刚做好的，按房间来）

- 经验：自己打怪得的经验立即本地 `gainXp`，同时攒进 `xpDelta` 随心跳上报；服务端按人累计 `xpTotal`；队友按**差额全额领取**（`claimedXp` 水位线，同图同层才领，第一次见某队友只记基线不补领；领到的经验不再进自己的 `xpDelta`，防回声放大）。
- 掉落：蓝装以上（极品 2 点及以上）与强化过的装备，多人时**不落地**，只有真正打死怪的人发起全队同层 Roll（`startRoll`）；服务端掷点 1–100，第一轮 30 秒、平局重 Roll 每轮 15 秒，未掷自动代掷，唯一最高者胜，胜者经 `claimRolls` 领进背包；队友那边同步生成的 Boss 掉落副本（归属 `__teammate__`）同档既不落地也不发起 Roll，防一件装备 Roll 出多件。白/绿（0–1 点）照旧落地，1 分钟队友归属保护。
- 颜色：极品点数 0 白 / 1 绿 / 2 蓝 / 3 红 / 4 紫 / 5 橙，强化过（`enh > 0`）彩虹色。

## 2. 服务端怪物状态设计（a）

### 2.1 世界单位：`(stageId, layer)`，共 49 个世界实例

- 一张图的一层 = 一个世界。玩家在不同层互相看不见（现在也是：`remotes` 按 `layer` 过滤），所以不需要跨层同步。
- **懒创建**：第一个玩家进入某层时创建该世界（按 `game-data.ts` 的层定义初始刷满怪 + 刷 Boss）；**无人后保留 5 分钟**（与联机版房间保留口径一致），超时无人则卸载，下次有人进重新按初始状态刷满。
- 世界常驻内存，不写数据库（与现在房间一致：重启/休眠即清空，见 §5.4）。玩家进度在存档库里，不受影响。

### 2.2 怪物对象（服务端版）

```ts
type ServerMonster = {
  id: number;            // 世界内唯一自增 id（客户端用它认怪）
  kind: string;          // 怪种 key（MONSTER_MAP 的 key，如 "jiangshi"；Boss 为 "boss"）
  x: number; y: number;
  hp: number; maxHp: number;
  spd: number; dmg: number; xp: number; r: number;
  boss: boolean; farmBoss: boolean;   // farmBoss = 尸王殿常驻尸王（不占 b.boss、不走通关）
  aggro: boolean; targetId: string | null;  // 仇恨目标玩家 id
  atkCd: number; slowT: number; stunT: number; teleportCd: number;
  seed: number; walkPhase: number;
  respawnAt: number;     // 死后重刷时间戳（普通怪用；Boss 另见 §2.5）
  def: { range: number; defV: number; mdefV: number; gold: number };
};
```

- 生成规则**沿用客户端现有口径**（`spawnEnemy` / `spawnBoss` 的同一套数）：`pool` 随机取种、`hpMul/dmgMul`、离玩家 ≥220、不压障碍物、白日门不进城不下海；初始进世界时一次性刷满 `monsterCount` 只（与现在“进图第一帧刷满”一致，玩家体验不变）。
- **多人血量加成要改口径**：现在按同房人数 `1 + 0.25 × (members − 1)`。世界里一层可能站 20 人，照此算普通怪血 ×5.75、Boss ×12.4，没法打。**推荐：加成按“当前在这只怪附近（仇恨/攻击范围内）的玩家数”算，上限按 4 人封顶**（即与现在 4 人房的上限一致，怪血最多 ×1.75、Boss 最多 ×2.8）。实现上简单做法：世界创建时按 4 人封顶定血量，不再动态调；更精细的做法是怪被多人围攻时再加血（不推荐，血量跳变体验差）。
- 位置与血量是服务端的唯一事实来源；客户端只做渲染与插值，不再本地改怪血。

### 2.3 服务端模拟（tick）

- **10Hz 定时 tick**（每 100ms 一次），只 tick 有玩家的世界；无人世界不 tick（怪静止，省 CPU）。
- AI 与客户端同款逻辑平移：游荡（`seed + elapsed × 0.35` 方向慢移，速度 ×0.22）、惊动（玩家进 120 或被攻击）、追击、近战（`atkCd 0.95s`）、远程怪射程内停步掷斧、沃玛教主瞬移（`teleportCd 3.5–5s`，距离 >190）。**但两处必须改**：
  1. **怪物间分离从 O(n²) 改空间哈希网格**（格子边长约 64px，只查邻格）。客户端一层 300 只怪每帧 4.5 万对配对还能跑，服务端 10 个世界 × 10Hz 照搬就是每秒 450 万对配对——必须改。
  2. **远程怪的飞斧（`eprojs`）**：服务端不逐帧模拟飞行物。推荐简化：远程怪进射程后按 `atkCd 1.5s` 直接对目标造成一次远程伤害（服务端记一笔，客户端收到伤害事件后自己画一支飞斧做演出）。飞行物只做表现，不进服务端状态。
- 障碍物碰撞与白日门规则（怪进不了城、下不了海）服务端也要有：**需要把 `game-data.ts` 里的障碍物/地形数据共享到服务端**（见 §7 Phase 1，这是整个改造的前置工作）。
- 怪物攻击玩家：服务端直接扣目标玩家血量（走现有心跳回包的 `hp` 字段同步，或走 worldSync 的玩家状态增量）。玩家死亡/复活流程不变（本地已有）。

### 2.4 刷新（respawn）——现在没有，世界制必须有

- 现状：怪死了不补刷，整层打空就空了（重进图才刷满）。世界是常驻的，不能打空了就永远空着。
- **推荐：普通怪死后 60–120 秒随机时间，在随机位置重刷一只同种怪，全层存活数上限 `monsterCount`**。重刷位置沿用刷怪口径（全图随机、不压障碍物；不强制离玩家 220——世界里到处都是人，强制 220 会刷不出来，改成离所有玩家 ≥120 即可）。
- 玩家进世界时看到的怪数：世界创建时刷满；之后随杀随补，长期维持在 `monsterCount` 上下。打怪体验与现在一致（怪永远有得打）。

### 2.5 Boss 与特殊机制（服务端版）

| 机制 | 现在（客户端/房间） | 世界制（服务端） |
|---|---|---|
| 层 Boss（一层一只） | 进图即刷，离玩家 850–1250；`bossSpawnMax` 谁先报谁定满血，`bossDamage` 累减，`bossState` 0→1→2 | **世界创建时刷一只**；血量由服务端定（4 人封顶加成）；死后 **15 分钟重刷**（给后来的人也能打 Boss、刷技能书）。通关判定与 Boss 重生脱钩（见下） |
| 通关（开传送门/记通关） | 本机 Boss 死 → `onBossKilled` → 开门/记 `cleared` | **Boss 死的那一刻，世界内所有在场玩家都开门**（等价于现在队友打死 Boss 时本机 `bossState = 2` 的路径）；已通关过的玩家（存档 `cleared` 有记录）进图即开门，不用等 Boss 死；Boss 重刷后**门不再关闭**（通关状态按人 latch，不按世界 Boss 状态回退） |
| 尸王殿（32 只尸王） | 进殿第一波按 6×6 格刷满，`bossRespawnT` 本地倒数 1 小时整波补满 | **服务端计时 + 服务端定格子**：世界创建刷满 32 只（1 只通关尸王占 `boss` 位 + 31 只常驻 `farmBoss`）；每小时整波补满空格（通关尸王不重刷）；格子分配由服务端算，所有人看到同一套位置 |
| 洞口黄衣僵尸（僵尸洞三层） | 玩家走近洞口 240 内触发爬出（本地 `holeZ` 动画 2.2 秒），爬出变真怪；杀掉置 `holeKillPending`，随心跳上报，全房一起点亮 | **洞口状态改为世界级**：爬出进度、僵尸是否已生成/已被杀由服务端管（多人走近只触发一次爬出）；杀掉后**杀手及其小队**点亮蜈蚣洞 + 沃玛寺庙（沿用现在“同房一起点亮”的口径，把“房”换成“小队”，见 §4） |
| 矿脉（僵尸洞，每层 4 条、各 3 次） | 每人本地各挖各的 4 条 | **改为世界共享**：4 条矿脉位置与剩余次数由服务端管，先挖先得，挖空等下一轮（建议随普通怪重刷节奏一起补，或每小时补满——实施时定） |
| 召唤宠（道士宝宝） | 本地 AI，打本地怪 | 宠的攻击走 `hitMonster` 事件上报（见 §3.3），目标必须是服务端怪 id；宠的位置/血量不进服务端状态（只做表现） |
| 火墙/施毒术等持续伤害 | 本地按 tick 扣本地怪血 | **火墙、毒等持续伤害由服务端按 tick 结算**（服务端记火墙区域与持续时间，在 tick 里给区域内怪扣血）；或客户端每跳上报一次 `hitMonster`（简单但作弊面大）。推荐服务端结算 |

## 3. 同步协议（b）

### 3.1 原则：继续走 HTTP，不引入 WebSocket（一期）

- artifact 客户端**没有任何 WebSocket 代码**，全是 `POST ./actions`（`api.ts` 是个 Proxy）。给客户端加 WebSocket 是大手术，且联机版服务端虽有现成 WS 服务端（`lib/game.js` 的 `/ws`），却是另一套旧房间实现、与 overlay 不互通。
- **一期用 HTTP 轮询**：心跳（1.2s）+ 新增 `worldSync`（500ms）。手感上限是 500ms 的位置更新 + 客户端插值（见 §3.2）。**二期可选**：把 `lib/game.js` 的 WS 服务端改造成世界推送通道，客户端再接 WS——那是另一个大任务，不放在一期。

### 3.2 新增动作 `worldSync`（500ms 轮询）

请求（客户端 → 服务端）：

```jsonc
{
  "worldKey": "19:0",        // stageId:layer，如比奇野外第 1 层
  "playerId": "...", "x": 123, "y": -456,
  "knownRev": 187            // 客户端已知的世界版本号（用于增量同步）
}
```

响应（服务端 → 客户端），**只含视野内的东西**：

```jsonc
{
  "rev": 188,
  "players": [ { "playerId": "...", "name": "…", "classId": "mage", "level": 11,
                 "x": 100, "y": -400, "hp": 320, "maxHp": 420, "gear": "…" } ],  // 视野内玩家
  "monsters": [ { "id": 1042, "kind": "jiangshi", "x": 130, "y": -380,
                  "hp": 540, "maxHp": 900, "aggro": true, "boss": false } ],      // 视野内怪（增量）
  "removed": [ 1011, 1037 ],      // 本次视野内消失的怪 id（死了/走出视野）
  "full": false,                  // 是否全量快照（进世界第一次 / 版本跳变时为 true）
  "boss": { "hp": 182000, "maxHp": 190000, "state": 1 },   // 本层 Boss 状态
  "events": [ { "t": "hit", "playerId": "…", "monsterId": 1042, "dmg": 137 } ]  // 附近的打击演出事件（可选）
}
```

- **视野半径：约 1000px**（玩家屏幕约一屏半）。一层 300 只怪全图散布时，视野内通常 20–60 只；每只怪快照约 40 字节 → 每次回包约 1–2.5KB，每秒 2 次 ≈ 每人 2–5KB/s 下行。50 人同时在线 ≈ 250KB/s 出口，免费版无压力。
- **增量 + 定期全量**：服务端给每个世界维护一个递增版本号 `rev`（怪生成/死亡/重刷/Boss 状态变都 +1）；客户端带 `knownRev` 来，版本连续时只发变化的怪（`monsters` + `removed`）；版本跳变（客户端掉线重连、切层）或进世界第一次发全量。客户端对怪位置做**线性插值 + 航位推测**（按上次移动方向与 `spd` 外推半拍），500ms 更新在手机上可接受。
- **只同步附近玩家**：`players` 只含视野内（同层、1000px 内）的玩家；超出视野的只在小地图上给个点（见 §3.4）。人再多也不卡，因为回包大小只与视野密度有关，与全服人数无关。
- **心跳（1.2s）保留**，但职责收窄：上报位置/血量/经验/外观（仍是 `xpDelta` 共享与 Roll 的载体，见 §4），返回 Boss 状态、共享击杀、Roll 列表、洞口状态。`worldSync` 与心跳各司其职：前者管“看见什么”，后者管“结算什么”。（也可以把心跳并进 `worldSync`、统一成 500ms 一次——实施时二选一，推荐先分开、风险小。）

### 3.3 伤害事件：新增动作 `hitMonster`

客户端打中怪时（普攻/技能/宠/火墙跳伤，命中判定仍在客户端做——与现在一致），发：

```jsonc
{ "worldKey": "19:0", "playerId": "…", "monsterId": 1042, "dmg": 137, "skillId": "fireball" }
```

服务端校验（缺一不可，否则丢弃并计数）：

1. 怪存在、活着、在该世界里；
2. 玩家在该怪的技能射程内（按 `SKILLS[skillId].range` + 约 150px 网络/走位容差；普攻 135）；
3. 伤害不超过按该玩家存档算出的合理上限（服务端有存档 JSON，可算面板与技能倍率；实施时定一个宽松上限，只拦改包的离谱数字，不拦正常暴击/极品）；
4. 限流：单人每秒伤害事件不超过约 30 次（自动战斗+多段技能的正常峰值）。

通过后服务端扣血、记最后一击；怪死时**服务端掷掉落、算经验**（见 §4）。未通过的事件直接丢弃（不回包报错，避免刷屏）。

> 作弊说明：这套校验拦的是“改包一刀秒 Boss”这类离谱行为，拦不住“微调伤害数字”的小作弊。休闲游戏接受这个口径；真要全服务端算伤害（服务端按玩家面板与技能倍率自己掷伤害）是二期工作，代价是技能系统要整个搬上服务端。

### 3.4 小地图与大地图

- 小地图（常驻右上角）：怪红点、Boss 橙点、队友蓝点——**只画视野内 + 队友**（数据来自 `worldSync`，与现在本地怪一致）。全图怪点不画（数据不在手里）。
- 大地图（点开小地图的全图视图）：现在画“整张地图全貌——怪物红点分布、Boss 橙点带名字、入口出口标记”。世界制下全图怪位置需要**单独拉一次**：新增 `worldMap` 动作（打开大地图时调一次，返回本层全部活怪的 `id/kind/x/y/boss`，约 300 个点 × 12 字节 ≈ 3.6KB，一次性），关掉即丢。平时不轮询。

### 3.5 进入世界（取代建房/进房）

- 现在：比奇城组队面板 → 建房（选图）或输码进房 → 大厅（1.5s 轮询成员）→ 点“进入游戏”进图。
- 世界制：**进图 = 加入世界**。从比奇城传送员传送、或走地图入口进图时，客户端调 `joinWorld({ stageKey, layer })`（无码、无房主、无大厅等待），服务端把玩家挂进该 `(stage, layer)` 世界、返回初始快照（全量怪 + 附近玩家 + Boss 状态），直接开打。
- 换层：走入口下潜/出口返回是**按人**进出世界（进新层 = 加入新世界，离老层 = 离开老世界）。**全房同步下潜的逻辑删除**（`advanceLayer` 的服务端字段与客户端跟随逻辑都不再需要）。
- 回城：回比奇城 = 离开世界（比奇城本身是安全区、无怪世界，只同步玩家位置，不用怪物模拟）。

## 4. 经验与掉落适配（d）

### 推荐：世界里保留 4 人小队（不要整图共享）

| 方案 | 规则 | 结论 |
|---|---|---|
| A. 整图所有人共享全额经验、蓝装全图 Roll | 任何人在图里打怪，全图人都得全额经验；蓝装以上全图所有人 Roll | **不推荐**。挂机蹭经验（站着不动也升级）；一件蓝装 20 人 Roll，弹窗刷屏、中奖率低、体验差；`xpTotal` 水位线要对全图人维护，`claimedXp` 膨胀 |
| **B. 保留 4 人小队（推荐）** | 玩家在世界里自由组 4 人小队；队内沿用现有机制 | **推荐**。刚做好的组队经验与 Roll 代码几乎原样复用，只是把作用域从“房间”换成“小队 + 同图同层”；不组队就是独行，体验与单人一致 |

**方案 B 的具体规则：**

- **组队**：小队最多 4 人（沿用 `ROOM_MAX = 4`）。建队/入队沿用现有房间列表 UI（见 §6：房间列表 → 小队列表）。小队只影响经验与 Roll，不影响进图（不组队也能进任何图）。
- **经验**：队内同图同层，沿用现有 `xpDelta → xpTotal → 差额全额领取`（`claimedXp` 水位线，领到的不进自己 `xpDelta`）；队外的人只拿自己最后一击的经验；不组队 = 只有自己的经验（与单人一致）。杀手判定：最后一击者得经验（服务端记）。
- **掉落**：
  - 白/绿（0–1 点）：落地，1 分钟归属保护（杀手优先），沿用现有拾取规则。
  - 蓝以上（2 点及以上）与强化过的：**只在杀手所在小队内 Roll**（沿用 `startRoll / submitRoll / claimRolls`，把 `roomCode` 换成 `teamId`，资格 = 小队内同图同层成员；30 秒首轮、平局 15 秒重 Roll、服务端掷点，全部不变）。杀手无小队时**直接进杀手背包**（不等 Roll，与单人一致）。
  - 金币/药水/技能书：落地，归属保护 1 分钟（杀手优先），沿用现有规则。技能书掉率（Boss 30%、普通 1.4%）不变，但 Boss 现在 15 分钟重刷一次，技能书产出节奏会变（见 §8）。
- **Boss 掉落**：Boss 死时服务端掷掉落，归属与 Roll 规则同上（杀手小队 Roll 或杀手自取）。**Boss 掉落去重**（只有打死怪的客户端发起 Roll）这个未验证点在世界制下自然消失——掉落由服务端一次性掷出，不再有“每人本地各生成一份”的问题。
- **共享击杀数 `sharedKills`**：房间级计数器随房间取消而删除。击杀显示改回本地 `kills`（世界制下不再需要全房击杀总数；通关也不靠它）。

## 5. Render 免费版容量与性能预估（e）

免费版配置：512MB 内存、共享 CPU、750 实例小时/月、15 分钟无人玩休眠、硬盘临时（每次部署清空）。

| 维度 | 估算 | 结论 |
|---|---|---|
| 内存（怪物状态） | 全 49 层刷满约 13,690 只怪 + 约 80 Boss，每只服务端对象约 200–300 字节 → **约 3–4MB**；玩家状态每人 <1KB | 绰绰有余。实际只建有人世界，平时远不到满额 |
| CPU（模拟 tick） | 10Hz tick，只 tick 有人世界；单世界 300 只怪一 tick 约 <1ms（含网格分离）；10 个活跃世界 ≈ 每 100ms 约 10ms，即 **约 10% CPU** | 20–50 人同时在线没问题 |
| CPU（HTTP 同步） | `worldSync` 每人 2 次/秒 × 回包 1–2.5KB；心跳 1.2 秒一次；50 人 ≈ 下行 250KB/s、上行可忽略；`hitMonster` 校验是纯内存查表 | 无压力 |
| 并发上限（免费版） | 瓶颈是 tick 与回包组装，不是内存。估算 **20–50 人同时在线**舒适；超过 50 人、或活跃世界 >15 个时，tick 与心跳 fan-out 会吃满共享 CPU，表现为怪移动卡顿、同步延迟变大 | 超过 50 人同时在线再升配置（Render Starter 1GB / Standard），不用现在升 |
| 磁盘/重启 | 世界状态纯内存；**部署/休眠重启后世界清空重建**（与现在房间一致）；玩家进度在 SQLite 存档库，不受影响；Boss 重生计时重启后归零（Boss 重生，接受） | 与现状一致，无新增风险 |
| 保活 | 现有 14 分钟保活 cron（`guo-fu-lian-ji-ban-keepalive`，ping `/api/health`）继续有效；世界制不改变休眠规则 | 不用改 |

> 补充：客户端渲染成本不变——现在单人一屏也要画 500 只怪，世界制下视野内怪数只少不多。手机端不新增负担。

| STALE_MS 漂移（artifact 20 秒 vs 联机版 5 分钟） | **实施前统一** | 世界制下“无人世界 5 分钟后卸载”与“离线玩家 5 分钟后清理”都按 5 分钟；artifact 侧 `STALE_MS` 从 20000 改为 300000，与联机版一致 |

## 7. 分步实施计划（g）

> 顺序不可乱：先数据共享（Phase 1），再服务端引擎（Phase 2），再协议（Phase 3），再客户端（Phase 4），最后移植部署（Phase 5）。每阶段都可独立验证、独立回滚。

### Phase 0 — 设计（本阶段，已完成）

- 产出：本文档。决策点：§4 方案 B（保留 4 人小队）、§6 房间取消/列表变小队列表、§2.4 重刷规则、§3.1 一期 HTTP。
- **需用户点头的决策**（实施前定）：① 小队列表是否保留房间码备用；② Boss 重刷 15 分钟是否接受（影响技能书产出）；③ 矿脉世界共享的补满节奏；④ 是否接受一期 HTTP 轮询的手感（怪位置 500ms 更新 + 插值）。

### Phase 1 — 数据共享模块（前置，约 1–2 天工作量）

- 把 `game-data.ts` 里的服务端需要的数据抽成**客户端与服务端共用的模块**：`MONSTER_MAP`（怪种数值）、层定义（`pool / hpMul / dmgMul / monsterCount / worldHalf / boss`）、掉落表（装备/技能书/金币/药水概率）、障碍物与地形（`obstaclesOf`、白日门海岸线/城界）、技能射程与倍率（供 `hitMonster` 校验）。
- artifact 服务端是 TS，可直接 import；**联机版服务端是纯 Node，不能直接 import TS**——需要把共享模块编译成 JS（或在联机版里维护一份同构的 JS 数据模块，定期从 artifact 同步）。这是 Phase 1 要解决的第一个工程问题。
- 验收：服务端能不依赖客户端跑通“按层定义生成一层怪”的单测。

### Phase 2 — 服务端世界引擎（artifact 先做）

- 新增 `worlds` 模块（artifact `server/src/` 新文件，联机版 `lib/` 对应内存版）：世界创建/卸载（懒创建、无人 5 分钟卸载）、初始刷满、10Hz tick（网格分离、AI 平移、远程简化、障碍物/白日门规则）、普通怪 60–120 秒重刷、Boss 15 分钟重刷、尸王殿服务端整波计时、洞口状态世界级、矿脉世界共享。
- 验收：单测（世界创建刷满数 = `monsterCount`；杀 10 只怪后 60–120 秒内补满；Boss 死后 15 分钟重刷；尸王殿整波 32 只）。

### Phase 3 — 同步协议与结算（artifact）

- 新增 `joinWorld` / `worldSync` / `worldMap` / `hitMonster` 四个动作（`worldSync` 500ms、增量 + 定期全量、视野 1000px）；心跳收窄职责（位置/经验/Roll/洞口），`roomCode` 改为 `worldKey + teamId`；`startRoll/submitRoll/claimRolls` 作用域从房间改为小队；`createRoom/joinRoom/leaveRoom/listRooms` 改为小队版（`createTeam/joinTeam/leaveTeam/listTeams`，或保留名字只改口径）。
- 验收：两客户端同进一世界，A 打怪 B 能在 500ms 内看到怪血条下降；A 杀怪 B 的视野里怪消失；伤害校验单测（超射程/超上限/超限流被丢弃）。

### Phase 4 — 客户端改造（artifact）

- `mode === "multi"` 时：关闭本地 `spawnEnemy/spawnBoss/spawnCorpseWave` 与本地怪物 AI，敌人改为服务端驱动（快照 + 插值/航位推测）；打击表现（投射物、伤害数字、技能特效）保留本地；掉落改为服务端事件驱动；小地图/大地图走服务端数据（大地图单独拉 `worldMap`）；Boss HUD 与通关判定走服务端 `bossState`；换层改为按人进出世界（删全房同步下潜）；组队面板改为小队列表；进图流程去掉大厅等待。
- **单人模式不动**（`mode === "solo"` 保持现有本地模拟，一行不改）。
- 验收：沙箱两客户端同图实测（怪同步、Boss 同步、Roll、经验共享、小队列表加入）；构建一次通过。

### Phase 5 — 移植到联机版并部署验证

- 按 v89 移植的既定流程：`actions-shim.js` 加世界引擎内存版 + 四个新动作，拷新客户端 bundle，更新推送清单，`npm test` 通过，走净化 staging 推送（**认领码 绝不能进公开仓库**），等 Render 部署后验证：`health` ok、新 bundle 200、两测试号同图进世界、怪同步、Boss 同步、Roll、经验共享、小队列表加入。
- **部署会清空认领与旧房间**（与历次部署一致）：用户部署后需用认领码重新认领、重新进图。世界制上线后没有房间了，旧房间自然消失。

### Phase 6 — 清理与收尾

- 删 artifact 侧 `rooms / room_members` 相关迁移与旧动作（走新迁移）、删联机版 overlay 房间代码、删 `lib/game.js` 与 `/ws`（`health` 改报世界数与在线人数）、统一 `STALE_MS` 为 300000、更新 `docs/PORTING-V89.md` 与本文档的实施记录。
- 验收：全量测试通过；线上实测（用户与朋友双真机同图）。

## 8. 风险清单

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 1 | **伤害作弊面**：伤害由客户端上报，`hitMonster` 校验只能拦离谱值 | 改包刷高伤、秒 Boss | 射程 + 伤害上限 + 限流三层校验；休闲游戏接受有限校验；二期可做全服务端算伤 |
| 2 | **位置漂移/不同步**：500ms 快照 + 插值，怪位置在客户端是估算值 | 怪看起来“瞬移”、打中判定与画面对不上（怪在 A 屏这里、在 B 屏那里） | 增量 + 定期全量校正；伤害判定以服务端位置为准（客户端只做表现）；实施时实测调视野与同步频率 |
| 3 | **Boss 经济变化**：Boss 从“进图一只”变“15 分钟重刷”，技能书（Boss 30%）产出变快；尸王殿整波服务端化后刷书节奏与现在一致但多人可同时蹲殿 | 技能书通胀、拍卖行书价波动 | Boss 重刷间隔实施前由用户定（15 分钟是推荐值，可调）；上线后看拍卖行数据再调 |
| 4 | **性能**：tick 与分离检测是新增的服务端 CPU 成本；O(n²) 若漏改会直接拖垮免费版 | 怪卡顿、同步延迟 | Phase 2 强制网格分离 + 只 tick 有人世界；上线前做 50 人并发压测（多开测试号进同一层） |
| 5 | **与房间列表任务冲突**：另一任务正在改同一批 artifact 文件（`listRooms`、组队面板） | 互相覆盖、构建冲突 | **本阶段只读不改**；世界制实施时先等房间列表上线，再以它为基础改小队列表（§6） |
| 6 | **客户端无 WebSocket**：一期 HTTP 轮询手感上限 500ms，怪移动不如本地模拟丝滑 | 手感下降（怪“瞬移”感） | 插值 + 航位推测；二期可接 WS（`lib/game.js` 有现成服务端，但客户端要新写） |
| 7 | **数据共享工程量**：`game-data.ts` 是 TS 客户端模块，联机版 Node 服务端不能直接 import | Phase 1 拖期 | Phase 1 先解决：编译成 JS 共享包，或联机版维护同构 JS 模块定期同步 |
| 8 | **单人模式回归**：客户端战斗代码是单人与多人共用的，改多人分支时容易碰到单人逻辑 | 单人模式被改坏 | Phase 4 以 `mode === "multi"` 分支隔离，单人分支一行不改；回归测试覆盖单人进图/打怪/通关 |
| 9 | **部署清空**：每次 Render 部署清空认领与世界状态（与现在房间一致） | 用户需重新认领（认领码）、重新进图；Boss 重生计时归零 | 与历次部署一致，用户已知；上线前明确告知 |
| 10 | **小队体验变化**：以前“进房即组队”，世界制下组队是可选的；不组队的人看不到队友经验共享 | 用户或朋友误以为“世界制 = 全图组队” | 上线说明写清楚：进图即同世界，组队（4 人）才共享经验与 Roll；小队列表一点即加入 |
