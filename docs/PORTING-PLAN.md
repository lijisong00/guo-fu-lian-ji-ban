# 联机版客户端移植方案（2026-11-23）

## 结论先行
**可以移植。**原版客户端（artifact `re-xie-chuan-qi-ge-cao-fu-wu-qi-ban` v89）与
独立联机版服务端是同一血缘：联机版 `shared/data.js` 就是从 2026-11-21
公开版导出逐项抄录的，怪物/地图/技能/装备表基本一致。移植 = 拿公开版
导出（86KB 单文件，`~/workspace/your_files/guo-fu-dan-ji-ban-2026-11-21/`）
当客户端底子，删掉它的本地模拟，改成服务端权威状态（`me` + `snapshot`），
再把房间/拍卖行接上。**不是重写**，是“换脑子（本地模拟→服务端）、留皮
（渲染/HUD/面板/摇杆）”。

## 评估发现：旧简版客户端为什么“完全不是一个东西”
旧 `public/app.js`（1529 行）是重新手写的极简客户端，问题不止是画得简陋，
协议层几乎全错——用户截图里的「操作失败」只是冰山一角：

| # | 问题 | 后果 |
|---|---|---|
| 1 | `onWsMessage` 没有 `case 'me'` | 服务端发的个人状态（血蓝/金币/背包/技能/CD/药水）全被丢弃，HUD 永远 `--/--` |
| 2 | 错误字段读错：服务端发 `{t:'error', msg}`，客户端读 `m.message \|\| m.error` | 所有服务端错误都显示成通用「操作失败」 |
| 3 | `enterGame()` 一进游戏就发 `{t:'shop'}`，当时还没进房间 | 服务端回「请先创建或加入房间」→ 正是用户截图里的「操作失败」 |
| 4 | `move` 发的是绝对坐标，服务端把它当方向向量 clamp 到 [-1,1]，且松开摇杆从不发 `{x:0,y:0}` | 角色一旦移动就永远朝右下角全速漂，停不下来 |
| 5 | `skill` 发 `skillId`（服务端要 `id`） | 点任何技能都报错「技能不存在」 |
| 6 | `set_active_skills` 发 `skills`（服务端要 `ids`） | 每次换技能都会把上场技能清空 |
| 7 | `buy` 发 `itemId`（服务端要 `equipId`）、`buy_potion` 只发 `tier` 且值是 small/mid/big（服务端要 `kind` + `s/m/l`）、`repair` 不带 `uid` | 商店买装备/买药/维修全报错 |
| 8 | `useBook` 同时发 `use_book` + `use_item` | 学完书第二条必报错 |
| 9 | 拍卖行 WS + HTTP 双发；`{t:'toast'}` 没有处理分支 | 服务端所有提示（金币不够、背包满了等）静默丢失 |
| 10 | 快照认人用 `p.deviceId`，服务端快照里玩家只有 `id` | 多人时永远认错自己 |
| 11 | 暗殿走 `enter_portal` + `teleport`（服务端要 `enter_passage`） | 连接通道进不去 |

## 移植方案
- **底子**：11-21 公开版导出（1495 行）：渲染（渐变体块+贴地阴影+发光眼）、
  HUD、背包/技能/传送/商店面板、小地图+大地图、摇杆/WASD/点按移动、飘字/特效。
- **数据**：直接复用 `shared/data.js`（已支持浏览器 `window.LegendData`），
  拷一份到 `public/data.js`，技能/职业/地图/怪物/装备全部以它为准，
  不再手抄一份。
- **怪物画风升级**：单机版旧导出（356KB）里有一套 Q 版矢量精灵
  （钉耙猫扛钉耙、僵尸爬行/矿帽/铁链/戴冠、蛇/猪/半兽人/骷髅等 40+ 造型），
  直接拼进新客户端替换公开版的渐变椭圆怪；缺造型的怪（蝙蝠/蜈蚣/祖玛/
  狼/双头）用通用体块 + 少量手写小精灵补。
- **协议层（全部按 `lib/game.js` handleAction 实测口径，不按过时文档）**：
  坐标中心原点（客户端 = 服务端 + w/2）；移动发方向向量，松开发 0；
  技能发 `{t:'skill', id}`；商店先 `{t:'shop'}` 再按回包渲染，买发 `equipId`、
  买药发 `{kind, tier:'s'|'m'|'l'}`、维修发 `{uid}`/`repair_all`；技能书发
  `{t:'use_book', bookId}`；上场技能发 `{ids}`；处理 `{t:'toast'}` 与
  `{t:'error', msg}`；进游戏自动建单人房（房间对单人不可见，朋友凭码加入）；
  拍卖行只走 WS（`auction_list/create/buy/delist/claim/claims`，字段按
  `server.js` 实测：`listings[].{id,sellerName,kind,item,price,expiresAt}`，
  书 kind 为 `skillbook`，领取用 `claimId`）。
- **保留**：设备 ID 存储（`lg_device_id` / `lg_api_base` / `lg_last_slot` /
  `lg_skillbar_pos`，一个字符都不改）；服务端、房间、拍卖行、认领逻辑、Render
  数据库与已认领角色全部不动。
- **声音**：公开版导出没有音频，v86 的 BGM/音效无法直接搬；新客户端内置
  一套极简 WebAudio 合成音（打击/施法/拾取/升级/死亡），无外部音频文件。
  BGM 暂不做。

## 移植中发现并修掉的两个服务端问题（客户端冒烟实测抓到，非纸面推测）
1. **拍卖行读写的是 DB 里的旧存档，不是内存里的活存档**（`server.js`
   `createAuctionListing` / `buyAuctionListing` / `claimAuctionClaim`
   全是 `store.getCharacter`，而游戏内一切改动只写内存 `player.save`，
   30 秒自动存盘才落库）。后果：在线玩家商店刚买的 / 刚打到的装备立即
   上架报「背包里没有这件装备」；买东西扣的金币、领取的金币/物品会在
   下次自动存盘时被内存旧存档覆盖丢掉。仓库自带测试是靠“离房存盘”绕
   过去的。修法：三处改成“在线玩家优先用内存存档，改完写库 + 置
   `meDirty`，离线玩家仍走 DB”（`server.js` 新增 `livePlayerFor`）。
   回归测试：`test/client-smoke.test.mjs`「在线玩家商店买完直接上架」。
2. **出城后永远回不来**（`lib/game.js` `teleportRoom` 只允许从比奇城出发，
   协议里没有任何回城手段；死亡也是原地复活）。修法：`targetId === 'city'`
   时任何地方都能回城，出城仍只能从比奇城传送员出发（与原版客户端
   一致）。客户端传送面板加了「回城」一行。回归测试：同文件「野外可直接
   传送回比奇城」。
- 另注意：商店买装备可能直接穿上身（`equipItem` 有空位就穿，不进背包），
  只有穿不上的（等级不够等）才进背包——这是服务端原有设计，客户端照此
  显示，不用改。
